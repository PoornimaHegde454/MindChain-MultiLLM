# Provider and Model Testing

This directory contains scripts to test all providers and models, and filter out non-working ones.

## Scripts

### 1. `test_providers_models.py`
Tests all configured providers and models to determine which ones are working.

**Features:**
- Tests provider health/availability
- Tests each model with a simple prompt
- Generates detailed JSON report
- Creates filtered configuration with only working models
- Provides summary statistics

**Usage:**
```bash
python test_providers_models.py
```

**Output:**
- `provider_model_test_results.json` - Detailed test results
- `working_models_config.py` - Python configuration with only working models

### 2. `apply_working_models.py`
Applies the working models configuration to `model_selector.py`.

**Features:**
- Reads `working_models_config.py` (generated by test script)
- Updates `app/core/model_selector.py` to only include working models
- Creates a backup of the original file
- Updates routing rules to use working models only

**Usage:**
```bash
python apply_working_models.py
```

**Note:** This script will ask for confirmation before making changes.

## Workflow

1. **Run the test script:**
   ```bash
   python test_providers_models.py
   ```

2. **Review the results:**
   - Check the console output for summary
   - Review `provider_model_test_results.json` for detailed results
   - Check `working_models_config.py` to see the filtered configuration

3. **Apply the working models (optional):**
   ```bash
   python apply_working_models.py
   ```
   
   This will update `app/core/model_selector.py` to only use working models.

4. **Verify the changes:**
   - Check that `app/core/model_selector.py.backup` was created
   - Review the updated `model_selector.py` to ensure it looks correct

## Configuration

Make sure your `.env` file has the necessary API keys:
- `GROQ_API_KEY` or `GROQ_KEY` - For Groq models
- `HUGGINGFACE_API_KEY` - For Hugging Face models
- `GITHUB_MODELS_API_KEY` - For GitHub Models (optional)

## Notes

- The test script uses a simple prompt: "Hello, this is a test. Please respond with 'OK'."
- Models are tested with `max_tokens=50` to minimize costs
- A small delay (0.5s) is added between model tests to avoid rate limits
- Failed models are logged with their error messages
- The filtered configuration automatically finds alternative models for routing rules when the original model is not working

## Troubleshooting

**No providers available:**
- Check your API keys in `.env` file
- Verify the keys are valid and have proper permissions

**All models fail:**
- Check your internet connection
- Verify API keys are correct
- Check provider service status

**Rate limit errors:**
- The script includes delays between tests
- If you still get rate limited, increase the delay in the script

**Backup file not created:**
- Check file permissions
- Ensure you have write access to the directory
